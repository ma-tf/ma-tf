# ADR 006: Machine-Readable Site Resources

## Context

The site publishes several files for crawlers, agents, and other tools. They do not all have the
same owner or purpose:

- `llms.txt` explains the site and points readers to canonical resources.
- `llms-full.txt` is intended to contain the full published-content archive.
- `openapi.json` describes the machine-readable resources published by the site.
- `.well-known/api-catalog` exposes those resources as an RFC 9264 linkset.
- `rss.xml` and the sitemap are generated by Astro.
- `robots.txt` is managed by Cloudflare.

Without an explicit contract, these files can drift apart. A guide can list a URL that no longer
exists, or a catalogue can claim ownership of a file generated by another system.

## Decision

Machine-readable site resources are a maintained public interface. Documentation for them must be
accurate, and each resource must have one clear owner.

The ownership model is:

| Resource                   | Owner      | Role                                                   |
| -------------------------- | ---------- | ------------------------------------------------------ |
| `/llms.txt`                | Repository | Concise site guide and discovery entry point           |
| `/llms-full.txt`           | Repository | Full published-content archive                         |
| `/openapi.json`            | Repository | OpenAPI description of application-owned resources     |
| `/.well-known/api-catalog` | Repository | RFC 9264 linkset generated from the resource catalogue |
| `/rss.xml`                 | Astro      | Blog feed generated from published content             |
| `/sitemap-index.xml`       | Astro      | Search and crawler index generated during the build    |
| `/robots.txt`              | Cloudflare | Crawler instructions managed outside the repository    |

`src/lib/resource-catalog.ts` is the source of truth for application-owned resources exposed by
`openapi.json` and `.well-known/api-catalog`. Astro-generated and Cloudflare-managed files may be
listed in `llms.txt`, but are not required to appear in that application resource catalogue.

The following rules apply:

1. `llms.txt` must link to canonical URLs and describe only behavior the site actually supports.
2. `llms-full.txt` must not claim to be complete while it is only a placeholder.
3. Every resource in `resource-catalog.ts` must have a stable URL and an accurate media type.
4. Generated resources must remain generated by their owning system rather than being copied into
   a second source of truth.
5. Changes to the public resource set must update the catalogue and the relevant documentation in
   the same change.
6. Redirects for these resources must be HTTP redirects, not meta-refresh or JavaScript redirects.

## Consequences

### Positive

- Agents and crawlers have a predictable entry point and resource map.
- Resource ownership is clear, including the Astro and Cloudflare boundaries.
- The OpenAPI document and API catalogue stay aligned through the shared catalogue module.
- The site can add or remove machine-readable resources without silently leaving stale links.

### Negative

- Public resource changes require documentation maintenance.
- The full archive needs either a generator or an explicit decision to keep it as a placeholder.
- Some resources are documented in `llms.txt` but intentionally fall outside the application
  catalogue.
